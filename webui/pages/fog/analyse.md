# Fog — Analyse › Chain (analyse.chain, analyse.block, analyse.glyphs)

- **The B24 detection chain cannot run in the core.** · `Encoding` is terminal in the adapter registry: no adapter consumes it, so "Encoding → SpanSet" (04 Drop detection) does not exist and the noise floor is a control inside the dSAX adapter, not a block. The web UI shows the chain as `demo.*` blocks with simulated runs; the live chain stays detrend → matrix_profile → threshold. · frames chain-1…1f, chain-3/4/6; spec §6.5 B24; REPORT §5 D-A1
- **Sub-second segments on a 1 Hz recording.** · Frames 1/3/4 show 0.2 s segments and 1.1–1.7 s drops on `M2_aug fs1` (1 Hz), which is impossible; the demo keeps the frame numbers and draws a 50 s span at a finer synthetic resolution. A real encoding block needs fs ≥ 5 Hz or segments ≥ 1 s. · frames chain-1, chain-3, chain-4; §0 canon (fs 1 Hz)
- **Time axis for a 50 s span in hours reads badly.** · §0 says hours since recording start; for 50 s that is "192.4000 h … 192.4139 h". The frames print "825 s … 875 s". Which wins for spans under ~20 min — hours with 4 decimals, or seconds since span start with the start hour in the chip? · frames chain-1 axis; §0 time display; REPORT D-A7
- **Stage numbering after a delete.** · Frame 1e keeps "04 Drop detection" after 03 was deleted; the demo renumbers (the chain now has three stages, so the survivor is 03). Stable numbers until the next save, or live renumbering? · frame chain-1e
- **Block index in the URL.** · Live smoke flows address `#/analyse/block/<i>` by 0-based step index (block/1 = 02 Matrix profile), while the interrogation and training block routes are 1-based (block/1 = 01). The analyse block route stays 0-based in both live and demo modes. · pages.ts; smoke.py analyse flow
- **Where does the noise-floor multiplier live?** · Frame 6 (02 Noise floor) has "cut k 8 σ = chosen in 03's sweep"; frame 3 (03 Encoding) has "noise floor 8 σ" in its parameters and the sweep. The demo stores k on 03 and 02's slider edits it (so 02 stays cached, 03 → 04 go stale). · frames chain-3, chain-6; B24
- **Registry size.** · Frame 2 says 21 blocks; frame 1g/1i add Span dedupe and frame 1h names Top-k motif pairs and Peak picker — 24 demo blocks. The glyph registry (6b) shows 21 and has no glyph for those three; they draw their signature glyph. · frames chain-2, chain-1h, chain-6b
- **Jobs store contract for an HPC job created in Analyse.** · "Create SLURM script" must make the job appear in Jobs (P24). There is no shared jobs store key yet; the demo writes `recordDemoWrite('jobs', 'add-job', {...})` and `setDemo('analyse.hpcJobs', …)`. See requests/analyse.md. · frame chain-1g; P24
- **Surrogate cost.** · The toolbar estimate ("≈ 0.6 s · 03 → 04") does not say whether the 200× surrogate run is included; the frame 1d footer says the surrogate run is "queued after". The demo halves the estimate when the surrogate is off. · frames chain-1, chain-1d; §6.3
