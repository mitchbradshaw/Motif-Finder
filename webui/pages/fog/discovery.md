# Discovery — frontend-design fog

- F1 · Which runs does the toolbar's `Create SLURM script for 2` cover? In frame 1 only `seed_E0102_bank` is `new` (sharkfin_v2 is already on the cluster, mp_drops_v3 is paused), so the shell counts pending runs honestly and reads `for 1`; the 1b underlay says `Run 2 queued`. · the count is the promise of how many jobs get created · frame discovery-1, §7.5
- F2 · `seed_E0102_bank` is labelled `new · local` yet its estimate (≈ 38 min) routes to the cluster; "local" cannot mean where it will run. The shell keeps the copy and treats it as "set up locally, not yet run". · users read `local` as where compute happens · frame discovery-1
- F3 · d-0412 contradicts itself across frames: the runs browser says `also found by seed_F03_native`, compare says step 7 is `only A fired` with B's nearest d 3.6 (near miss). The shell follows compare (IoU ≥ 0.5 match) and shows `also found by —` plus a muted near-miss line. · "also found by" and set overlap must use the same matching rule · frames discovery-1 vs discovery-3
- F4 · Detection duration vs windows: frame 1 draws d-0412's band ~0.1 h wide in a 0.8 h view; frame 3 calls the window 40 s but labels its axis 192.39–192.41 h (72 s) and draws the span as ~10 % of it. The shell uses a 36 s detection and a 40 s window. · durations are shown in s and must agree with the band a user sees · frames discovery-1, -3, -3b, §0 time display
- F5 · Where each run fires omits the paused mp_drops_v3 and the new seed_E0102_bank while the runs list shows them; §7.2 says a running run shows its unfinished part. The shell draws only runs with results or running, and lists the rest in a one-line "not drawn" foot. The scoreboard adds a paused row (§7.3 "says so across the row"). · a missing row looks like "fires nowhere" · frame discovery-1 vs §7.2/§7.3
- F6 · seed_E0102_bank's stripe is rose/red; §3 reserves red for artifact/destructive. The shell uses a non-semantic rose (#E2557E) — still close to red. A run palette distinct from verdict colours and family colours (D8) is needed. · colour semantics · frame discovery-1, §3
- F7 · Runs count differs across frames (`5 in this session` in frame 1, `4` in 1b/2/3 which omit mp_drops_v3). The shell uses one session (frame 1) everywhere. · frame discovery-1 vs -1b/-2/-3
- F8 · Frame 1c gives fires for CH8_B2 / CH9_C1 / CH11_C2 but no scores; adding channels to a finished run's scope implies the run covered them. The shell generates demo score rows for any channel and, when the recording changes, marks runs stale. Whether adding a channel should mark runs stale (they did not run there) is unspecified. · a scoreboard total silently growing with scope is a claim the run never made · frame discovery-1c, §7.1
- F9 · 1b draws per-channel checkboxes under "Channels in scope" while §7.5 says each template becomes one run across all channels. The shell renders them checked + disabled with the reason. · frame discovery-1b vs §7.5
- F10 · History popover content, the scope-chip click and the Preview-on-a-sample result on the runs page are not drawn. The shell: History lists r-0431 / r-0415 / r-0412 / r-0398 with Open; scope chip scrolls to the Scope card; preview result is an inline strip under the Scope header. · no frame · §7.1
- F11 · `recall · reviewed overlap` pooled "0.71 over 14 h" equals CH4_A2 alone while CH7_B2 has 6 h reviewed ("too few"): the shell assumes too-few channels are excluded from pooling. · the pooling rule is what makes recall comparable · frame discovery-1, §7.3
- F12 · Changing the recording with runs in the session — the consequence is not specified; the shell asks to confirm, resets channels to the first three, and marks runs stale. · §7.1
- F13 · The seed card's provenance line reads `825–846 s` while §0 puts times in hours since recording start (durations in s). The shell shows `0.23 h · 21 s` and keeps the sample count. · a second time convention on one page is how a reader mis-reads an hour for a second · frame discovery-2, §0
- F14 · `window m` is drawn as an open Select but §7.6 says the window is locked to the exemplar's native length. The shell renders it disabled with a lock and the reason. · an editable-looking control that cannot be edited is a dead click · frame discovery-2 vs §7.6
- F15 · `seed_E0102_bank` is "E-0102 · 3 lengths" while the seed page offers `scale bank none` and says MASS takes one seed. Which algorithm runs a scale bank, and whether it is still MASS, is unspecified — the shell disables the 3-lengths option with "needs a scale-bank algorithm". · the runs list promises a capability the setup page denies · frames discovery-1, -2
- F16 · What the seed histogram's surrogate distribution is computed on (circular shift of the same channel, pooled over channels, per-seed) is not stated; the shell fixtures one null series for the scope. · "null gives 6" is the number a threshold is chosen against · frame discovery-2, §7.6
- F17 · Saving a draft as a template: whether a draft must have been run first, how versions are numbered, and what happens on a name collision are unspecified. The shell requires a unique name matching `^[a-z0-9_]{3,40}$` and allows saving an unrun draft. · §7.6, Library 7
- F18 · Role order: §7.7 lists `Source · Preprocess · Encode · Score / estimate · Detect`; frames 3 and 3b draw `Score / estimate` (02) before `Encode` (03), which is the B24/§0 chain order. The shell follows the frames. · a column order that disagrees with the chain order makes "first differing stage" read wrong · frame discovery-3 vs §7.7
- F19 · The IoU ≥ 0.5 matching rule is shown as a caption with no way to see or change it; Settings › Analysis defaults is named nowhere on the page. Every only-A / only-B count depends on it. · frame discovery-3, §7.7
- F20 · Comparing a run that is still running (sharkfin_v2 at 64 % on the cluster) is allowed by the runs list's pick boxes but no frame says what the overlap counts mean for a partial run. The shell lets it be picked and counts what exists. · a partial run's "only A" is not a disagreement, it is unfinished work · frame discovery-3, §7.2
- F21 · Role assignment for an arbitrary chain (which stage is the Score / estimate stage) is assumed to come from the block contract; §6.8 does not declare a role per block. The shell maps by glyph. · without a declared role, two chains cannot be aligned at all · §6.8, §7.7
- F22 · Human annotations as a side: precision and × null have no meaning for the human reference (the shell shows `—` and `0 reviewed`), and "only B fired" for a human verdict is a miss by the machine, not a disagreement between algorithms. The frames do not cover this case although §7.7 allows it. · §7.7
- F23 · `Seeded search  Signal + exemplar → Scores` has no row in the §6.8 contract table, and B25 calls seeded search a Discovery mode rather than a chain block — yet 3b renders it as a stage with a contract signature. The shell fixtures it. · a renderer built from the contract table cannot draw this card · frame discovery-3b, §6.8, B25
- F24 · `≈ 1 s re-run on 40 s`: whether stepping re-runs both chains locally on the window or reads cached intermediates is unspecified, and it decides whether stepping is free. The shell simulates a ~1 s re-run. · frame discovery-3b
- F25 · 3b labels Drop detection `Signal → SpanSet` while the canon (B24 / §0) says `Encoding → SpanSet`, and its noise-floor numbers (`σ 0.0096`, `cut ±0.077`) carry no units where §3 asks for mV. The shell uses the canon signature and adds mV. · frame discovery-3b vs §0/§3
