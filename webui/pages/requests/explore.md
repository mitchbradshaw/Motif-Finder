# Kit / shared requests — explore unit

Worked around locally in `webui/client/src/explore/`; listed so the kit owner can promote them.

- **`charts/useSize` should follow a swapped element** · where: `webui/client/src/charts/useSize.ts` · why: it binds its ResizeObserver once on mount, so an element that mounts later (a tier that appears when a drawer closes, a deep link that opens with the drawer open) stays at width 0 and the plot never fetches. Workaround: `explore/useElementSize.ts` (callback ref). A callback-ref version in charts would fix every page that conditionally renders a plot.
- **`IconButton` should forward a ref** · where: `kit/display.tsx` · why: an (i) button that anchors a controlled Popover (legend popovers on Corpus and Signal, reachable by `?popover=`) needs a ref; `InfoTip` is uncontrolled so it cannot be deep-linked. Workaround: a plain `<button className="k-icon-btn bordered">`.
- **Controlled `InfoTip`** (`open` / `onOpenChange`) · where: `kit/surfaces.tsx` · why: frames 1b and 2a make legend popovers deep-linkable states; today each page rebuilds the button + Popover.
- **`MultiPick` (checklist select chip)** · where: kit forms · why: "runs all · 34 ▾" / "method any · 7 ▾" (Corpus), channels "6 of 16 ▾" (Cross-channel) and every multi-valued filter are a trigger styled like `Dropdown` opening checkboxes with select all · none. Local: `explore/bits.tsx` `MultiPick`.
- **`Seg` buttons are `role="radio"`** · where: `kit/nav.tsx` · why: `webui/smoke.py` clicks the colour-by buttons with `get_by_role("button", name="both")`; Corpus therefore keeps its own `.seg` buttons. Either smoke.py should accept radios or Seg should offer a `role="button"` mode.
- **`Table` with external sort + paging** · where: `kit/Table.tsx` · why: a paged table (drawer, 6 rows a page over 412 rows) must sort the whole filtered set before slicing; Table sorts only the rows it is given. Workaround: controlled `sort` + sorting in the page. A `pageSize` prop that sorts then pages would remove that.
- **Table header select-all is page-scoped** · where: `kit/Table.tsx` · why: selection across pages needs the page's keys merged into the full selection (`mergePage` in `explore/SignalDrawer.tsx`) and a "select all 412" follow-up link.
- **`Breadcrumb` item testids** · where: `kit/nav.tsx` · why: smoke relies on `crumb-corpus`; kit Breadcrumb has no per-item testid, so Explore keeps its own crumb markup.
- **Header demo chip tooltip copy** · where: `shell/Header.tsx` · why: inventory asks for "numbers in the marked cards are §0 placeholder canon, not your database" on live pages with demo regions (Corpus, Signal) — today's copy says "nothing here is read from … a database", which is false on those two pages.
- **An "Explore spans" review queue id in canon** · where: `fixtures/canon.ts` `REVIEW_QUEUES` · why: `Review this motif`, `Take span for Review`, `Send selected to Review` and Cross-channel's `Review this window` all stage into it (demo writes `explore/stage-*`); Review has nowhere to show them.
