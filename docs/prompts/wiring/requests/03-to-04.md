# Requests from Prompt 03 (library) to Prompt 04 (discovery)

## 1. The library table shapes are published — build against them, do not invent them

`docs/LIBRARY_STORAGE.md` is on `main` (commit `52f7950`). **Sections 2 and 3 are contract** and will not
change under you: the identity rule, the hash constants, and the DDL of every table the Library owns.

What you will most likely want:

- **An exemplar to seed a search from.** `motif_entry` is the shape; `motif_member` is one occurrence of it.
  `motif_entry.content_hash` is the identity — spec §10.4 says a seed search's exemplar *"keeps span,
  recording, channel, content hash and the run's recipe hash"*, and all five are on the row after
  Prompt 03's additive columns (`content_hash`, `channel`, `fs`, `source_kind`, `source_store`,
  `source_ref`).
- **Templates.** There is **no second template store**. Spec §4.5: a saved detection algorithm *is* the
  `templates` row. The Library's Templates section reads that same table; so should Discovery's picker.
  If you need a column on `templates` that is not there, add it additively and tell me — do not create a
  parallel table.
- **Families.** A family is not a column on an entry. It is a row in `grouping_assignments` belonging to a
  saved `groupings` row (`family_id`, `family_label`, `distance`, `is_medoid`). Read the grouping you want
  by id; there is no single global family assignment, because §8.2 keeps earlier groupings saved.

## 2. The identity rule, in one line, so our two matchers agree

`Working.library.identity.content_hash(values)` — resample the waveform to **256** points, z-normalise,
round to **6** decimals, blake2b-128, hex. It reuses `Working.distances.resample_to_length` and
`z_normalize`, so **the hash and `scale_invariant_distance` agree on what "the same shape" means**: a pair
at distance 0 hashes the same. If your seeded search needs to ask "have we seen this shape before", call
that function rather than writing a second rule.

Near-duplicate is spec §4.6 — reciprocal IoU ≥ 0.5 plus onset agreement within **0.25 × the candidate's own
duration**. The 0.25 is Prompt 03's default (the spec gives no coefficient) and lives in
`Working/library/dedupe.py` as `ONSET_TOLERANCE_FRACTION`. Import it; do not re-declare it.

Careful: **there are two different 0.5s** in this project. §4.6's IoU ≥ 0.5 is a span-overlap match
threshold. §9.10's "omit motifs whose nearest family is past d > 0.50" is a shape-distance omit cut. They
are unrelated numbers that happen to share a value.

## 4. Two things that will bite you, found while reading the data

1. **`Plots/drop_motifs11/sequences.csv` binds to `Plots/drop_motifs10/motifs`, not to the tracked seed
   bundle.** All 118 sequences resolve their endpoint event ids against drop_motifs10 and **zero** against
   `DATA/library_seed/drop_motifs5`. If you reach for "the seed data" for sequence work, that is the wrong
   store.
2. **Exclude the `reishi_1hz` control corpus** (256 rows in drop_motifs10) from anything that groups by
   `(catalogue_id, channel)`. It shares those keys with `reishi_10hz` and differs only by `fs`, so it
   double-counts the same organism: the sequence-recovery rule reproduces **118/118** sequences with it
   excluded and only **52/118** with it in.
