# Requests from Prompt 02 (settings / registration) to Prompt 03 (library)

- **Library shelves: read the registry, do not rescan.** `api.ts::getRegistry('window_set')`,
  `getRegistry('drop_motif_store')` and `getRegistry('catalogue_spreadsheet')` return the registered rows
  (`registered_artifacts`, `active = 1`) with `path`, `params` and the sidecar `manifest`. Window sets shelf =
  the `window_set` rows; the seed data = the `drop_motif_store` rows (the `DATA/library_seed/drop_motifs5/
  motifs` store registers with `params.n_events = 410`, `params.spans` = the 16 span keys, `params.recording_ids`)
  and the `catalogue_spreadsheet` row (`params.rows` is NOT stored — only `n_rows`, `columns`, `unparseable`;
  re-read the xlsx with `Working/registration/kinds.py::_check_catalogue` or `openpyxl` when importing).
- **Importing a store's events into `motif_entry` / `motif_member` is yours.** 02 registers the store only
  (checks: the three files, required columns, every event has its snippet, unknown `recording_id`s and fs
  mismatches as warnings). Two facts to carry: `events.csv` indices are ABSOLUTE in the source channel; the
  seed's `source_file` column says `CH0.npy` (not a `.mat` name) — bind by `recording_id`, which in the seed
  are this database's ids (1, 3, 8, 10, 20–29, 33–35, 385).
- **A window set you write should follow the convention** in `docs/DATA_REGISTRATION.md`:
  `DATA/derived/window_sets/<name>/windows.npz` (`starts, length, fs, source_file, channel[, labels]`) +
  `manifest.json` (`kind: "window_set", name, recording, channel, fs, length, n_windows, labels_source`), then
  `POST /api/registry/window_set/register` — or write the `registered_artifacts` row yourself through
  `writes.write_machine` with `kind = 'window_set'`.
- **Vocabulary tags.** Settings › Vocabulary reads `tag_vocabulary` when it has rows (name + definition) and
  otherwise shows the six proposed shape tags with zero members. If the Library writes tags, write them to
  `tag_vocabulary` (human table, `writes.write_human`) and the page follows.
- **Library groupings defaults** are in the `settings` table under page `library-groupings` (`unit`, `basis`,
  `cut`, `omit_d`, `omit_min`, `seq_gap`, `seq_events`, `w_shapes`, `w_gaps`, `fb.<basis>.*`):
  `GET /api/settings/library-groupings` → `values`.
